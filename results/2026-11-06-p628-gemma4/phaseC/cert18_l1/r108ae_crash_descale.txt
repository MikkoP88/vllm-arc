Root cause — two caller forms, one kernel contract:
  - vxk _normalize_descale_tensor asserts the descale has 1-element
    storage (per-tensor scalar; dtype fp32 passes the shape through
    as-is, bf16/fp16 get flattened+cast+re-expanded).
  - ENGINE path (triton_attn.py:637): k_descale = layer._k_scale.expand(
    descale_shape) — scalar storage -> PASSES untouched.
  - WARM gate (gpu_worker.py _arc_xpu_warm_points, cert12 kit):
    kd = torch.ones(nkvh, device=dev).expand((1, nkvh)) — nkvh-element
    storage -> REJECTED (microbenches r108ac/ad used the expand-of-
    scalar form, so this caller form was never exercised).

Fix (patch v3, commit 0a9b2c34): _arc_fa2_scalar(ds) helper at module
level — pass-through when storage is already 1 element (engine path,
zero cost), else ds.reshape(-1)[:1].clone() (element 0 into fresh
storage). Exact for per-tensor scales: per-token-head kv modes are
guarded off in the dispatch condition, so the descale is uniform by
construction. Local verify: applied to cert17 base, 3 marks, AST-valid,
dispatch at line 993 between def (869) and sinks (1002), idempotent.

(marker line + both Worker/EngineCore tracebacks; container paths only,
no host addresses).
